# WhestBench 新100排名、跨MLP方差与筛选阈值

本文汇总以下两部分实验结果：

1. 15个 estimator 在原本地 full-100、官方 public-50、两个独立新50及合并新100上的排名和分数；
2. 每种方法在不同随机 MLP 上的分数方差，以及 self-evolve 候选晋级需要跨越的统计阈值。

## 实验口径

- 新生成100个 width-256、depth-32、无偏置、ReLU MLP；
- 权重独立服从 `N(0, 2/256)`，保存为 float32；
- 100个 root seed 全部唯一，分成互不重叠的新50-A和新50-B；
- 每个 MLP 使用8次独立 scrambled Gaussian Sobol，每次65,536点，共524,288点估计真值；
- 15个 estimator 均使用已核对哈希的真实源代码；
- 使用官方 subprocess runner 和 Phase-1 FLOP budget；
- 共完成 `15 × 100 = 1,500` 个 estimator/MLP 预测，0 failure；
- 新50和新100使用去除真值噪声后的 FLOPs-only adjusted score，避免本地并发 wall-clock 污染；
- 以下分数越低越好。

## 方法比较需要跨越的阈值

self-evolve不应直接比较两个方法各自的独立方差，而应在相同MLP上计算配对差值：

```text
delta_i = candidate_score_i - incumbent_score_i
```

候选晋级规则应为：

```text
mean(delta) + threshold < 0
```

下表数值单位为 `×10⁻⁷`，是全部105个方法对的阈值中位数和90分位。

| MLP数 | 单候选单侧95% 中位/q90 | 双侧95% 中位/q90 | 同时试15个候选Bonferroni 中位/q90 |
|---:|---:|---:|---:|
| 50 | 0.908 / 1.191 | 1.088 / 1.427 | 1.534 / 2.013 |
| 100 | 0.636 / 0.834 | 0.759 / 0.997 | 1.061 / 1.392 |
| 200 | 0.447 / 0.587 | 0.534 / 0.700 | 0.742 / 0.974 |
| 400 | 0.316 / 0.414 | 0.376 / 0.494 | 0.522 / 0.685 |

例子：

- 新100第1名 #317463 与第2名 #317473只差 `0.0416e-7`；
- 二者配对单侧95%阈值约为 `0.485e-7`；
- 实际差距比阈值小约12倍，因此无法认为第1名真正优于第2名；
- 排名不等于方法之间存在统计可辨识差异。

## 对self-evolve的建议

1. 所有候选必须在与incumbent完全相同的MLP上做配对比较。
2. 50个MLP、单个预先指定候选，通常至少需要改善约 `1.0e-7`。
3. 100个MLP、单个候选，通常至少需要改善约 `0.6e-7–0.8e-7`。
4. 一轮同时测试15个候选时，100个MLP建议至少跨过 `1.1e-7–1.4e-7`。
5. search suite只能用于生成和初筛，不能同时作为最终晋级依据。
6. 建议使用search-50筛选，再用从未反馈给搜索过程的holdout-50决定晋级。
7. 如果持续迭代，应轮换或重新生成holdout MLP，防止对固定suite发生winner's curse。
8. 新100排名更适合作为报告结果，不应反复反馈给self-evolve作为优化目标。

当前数据只能估计跨MLP方差。若需要进一步分解“同一MLP上不同随机seed重复运行”的方差，需要对每个方法/MLP增加多次独立 estimator 重复。
